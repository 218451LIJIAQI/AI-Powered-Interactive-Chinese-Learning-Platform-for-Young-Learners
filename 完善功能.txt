你现在要作为产品完整性审计负责人、全栈架构审计专家、上线前功能完整度 QA 和 execution flow 验收负责人，检查整个项目是否存在任何“未开发完、半成品、假实现、需要继续完善、入口已开放但功能不完整”的功能。

你的任务不是普通测试，也不是只检查 bug。

你的任务是确认：

整个产品是否还有任何功能没有真正完成。
任何页面、按钮、入口、接口、流程、角色权限、业务状态、错误状态、数据状态，只要存在“不完整、未接通、假实现、mock、TODO、占位、不可用、逻辑缺失、流程断裂、体验不完整、需要继续完善”的地方，都必须被发现、记录、修复或标记。

============================================================

============================================================

请主动检查并处理以下情况：

- 页面存在，但数据没有真实接通
- 按钮存在，但点击无反应
- 按钮存在，但只是 console.log
- 表单存在，但没有真实提交
- 表单提交后没有真实业务效果
- API 调用了，但后端没有真正处理
- 后端接口存在，但前端没有接入
- 前端入口存在，但后端接口缺失
- 路由存在，但页面是占位内容
- 页面显示 Coming soon / TODO / Placeholder
- 代码里存在 TODO / FIXME / stub / mock / dummy / fake / hardcoded / temporary
- mock provider 泄漏到真实业务流程
- no-op service 伪装成成功
- fallback 行为伪装成真实结果
- hardcoded 示例数据被当成真实数据展示
- 用户完成操作后状态没有更新
- 页面刷新后数据丢失
- 权限角色路径不完整
- student / teacher / admin 任一角色功能不完整
- 后端 domain 存在，但前端没有入口
- 前端页面存在，但后端 domain 没有实现
- 数据库表存在，但没有完整业务流程
- API 文档写了，但真实接口不存在或行为不一致
- 菜单入口存在，但页面功能未完成
- dashboard 卡片存在，但点击后无完整流程
- 支付 / 退款 / 权益流程有假成功或未接通
- AI 功能有假回复、假 fallback、未接 provider、未处理失败
- 上传 / 下载功能只做了 UI，没有完整存储、权限和错误处理
- notification / moderation / audit 只有部分实现
- loading / empty / error / success 状态缺失
- 关键 edge cases 没有处理
- 关键业务流程没有测试
- 关键功能没有端到端验证

============================================================
检查方式
============================================================

你必须同时从 4 个角度检查：

1. 产品功能角度
- 检查所有页面、导航、按钮、表单、弹窗、菜单、dashboard、列表、详情页、设置页。
- 判断每一个用户能看到的功能是否真实可用。
- 判断是否存在“看起来有功能，但实际没完成”的地方。

2. 前端代码角度
- 搜索 TODO、FIXME、mock、stub、dummy、fake、placeholder、coming soon、not implemented、console.log、hardcoded sample data。
- 检查 route、component、hook、service、API client、state management。
- 检查是否有未接 API 的 UI。
- 检查是否有写死数据、假数据、临时逻辑。

3. 后端代码角度
- 搜索 TODO、FIXME、mock、stub、dummy、fake、placeholder、not implemented、no-op。
- 检查 controller、service、repository、provider、DTO、migration、test。
- 检查是否有返回假成功、空实现、未完成 provider、未完成 payment / AI / upload / audit / notification 逻辑。
- 检查是否有接口存在但没有真实业务效果。

4. 浏览器真实操作角度
- 启动项目。
- 用真实浏览器打开每个页面。
- 逐个点击所有可点击入口。
- 逐个提交表单。
- 逐个走核心 execution flow。
- 检查 console 和 network。
- 验证操作后数据库 / UI / API 状态是否真的变化。
- 检查刷新页面后状态是否仍然正确。
- 检查不同角色下功能是否完整。

============================================================
完成度判断标准
============================================================

每个功能必须按下面标准判断：

- COMPLETE：真实可用，前后端接通，状态正确，错误处理完整，刷新后仍正确，有基本验证。
- PARTIAL：部分可用，但还有缺失、边界问题、未接通状态或体验缺口。
- STUB：看起来存在，但主要是假实现、mock、placeholder 或 no-op。
- MISSING：产品上应该存在或入口暗示存在，但实际没有实现。
- BLOCKED：因外部服务、账号、环境、密钥、第三方 provider 等无法验证。

不要把 PARTIAL / STUB / MISSING 说成 COMPLETE。
不要因为 UI 有页面就认为功能完成。
不要因为接口返回 200 就认为功能完成。
不要因为 happy path 通过就认为功能完整。
不要因为 mock 数据能显示就认为真实功能完成。

============================================================
发现问题时必须处理
============================================================

对于每个未完成点：

如果可以安全修复：
- 直接修复
- 接通真实 API
- 删除假数据或明确隔离 demo
- 实现缺失逻辑
- 补充 loading / empty / error / success 状态
- 修复按钮、表单、路由、权限、状态更新
- 补测试
- 重新验证

如果不能安全修复：
必须记录：
- 功能名称
- 文件路径
- 页面 / 路由 / endpoint
- 当前状态：PARTIAL / STUB / MISSING / BLOCKED
- 用户影响
- 为什么不能直接修复
- 需要什么信息或决策
- 推荐优先级

输出格式
============================================================

最终输出必须包含：

1. Completeness Audit Scope

2. Feature Completeness Matrix

- feature
- frontend status
- backend status
- integration status
- browser verification status
- final status：COMPLETE / PARTIAL / STUB / MISSING / BLOCKED

3. Incomplete / Unfinished Features
每一项必须包含：
- severity
- feature
- page / route
- endpoint / backend object
- file path(s)
- evidence
- actual current behavior
- expected complete behavior
- user impact
- recommended fix
- status：fixed / open / blocked

4. Stub / Mock / Placeholder Findings
列出所有：
- TODO
- FIXME
- mock
- stub
- dummy
- fake
- hardcoded
- no-op
- placeholder
- coming soon
- not implemented
- console.log-only behavior

每一项必须说明是否已修复，没修复的原因是什么。

5. Implemented Fixes
- 修改了哪些文件
- 修复了什么未完成点
- 如何确认不是假实现
- 重新验证结果

6. Verification
- 运行了哪些命令
- 浏览器检查了哪些页面和流程
- console / network 结果
- 数据状态是否验证
- 未验证项目和原因

7. Remaining Work
只列真实剩余未完成项：
- 功能
- 文件路径 / 页面 / endpoint
- 当前缺口
- 需要的下一步
- 优先级

8. Final Assessment
- 是否还有未开发完的功能
- 是否还有半成品功能
- 是否还有 mock / no-op / placeholder 泄漏
- 是否还有入口开放但流程不完整
- 当前是否可以上线
- 如果不能上线，最关键的阻塞是什么

============================================================
停止条件
============================================================

只有全部满足以下条件，才可以说完成：

1. 所有页面入口都检查过。
2. 所有主要按钮和表单都检查过。
3. 所有核心 execution flows 都检查过。
4. 前端代码中 TODO / FIXME / mock / stub / dummy / fake / placeholder / hardcoded / console.log-only 行为都搜索过。
5. 后端代码中 TODO / FIXME / mock / stub / dummy / fake / no-op / not implemented 都搜索过。
6. 所有发现的 STUB / MISSING / PARTIAL 高风险功能都已修复或明确 blocked。
7. 浏览器验证、代码验证、API 验证之间没有明显矛盾。
8. 没有入口已开放但功能实际未完成的高风险问题。
9. 最终报告列出了真实剩余工作和上线判断。

如果没有满足这些条件，不允许说完成，必须继续检查或修复。
