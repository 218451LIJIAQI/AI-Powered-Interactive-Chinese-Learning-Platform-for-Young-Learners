# 生产就绪审计核验与整改记录

核验日期：2026-05-25。本文以当前仓库源码为依据；“待推进”表示确实有价值，但不应冒充已经完成或生产阻断级缺陷。

## 结论摘要

- 原报告识别到了真实风险，尤其是 AI 调用的事务边界、AI 成本保护、部署资料与安全头。
- 若干结论被夸大或已过时：真正调用同步 AI provider 的事务方法是 6 个而非 8 个；Actuator 已存在；上传端点已有较小业务层限额；CI 已有两个 job；`backend/uploads/` 已被忽略。
- “确保满分”不能由代码修改保证。可验证目标应是：风险有证据、变更有测试、剩余工作有清晰优先级。

## 本次已落实

| 事项             | 落地内容                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 长事务与 AI 调用 | 六个文本 AI 路径移除外层事务；学习推荐仅以短只读事务提取上下文，provider 调用发生在事务结束后；发音/书写文件复制也移出事务，仅元数据写入使用短事务                                                                  |
| 数据库连接配置   | Hikari pool/minimum idle/connection timeout 改为环境变量控制                                                                                                                                                        |
| AI 成本保护      | 新增单实例用户级 AI provider 限流，默认 10 次/分钟及 100 次/天                                                                                                                                                      |
| 外部邮件         | 密码重置和教师审核邮件改为提交后异步投递，避免 SMTP 占用业务事务；生产启动强制要求 SMTP 可配置投递                                                                                                                  |
| 安全响应         | 后端及 Nginx 添加 CSP；CORS 改用显式 methods/headers                                                                                                                                                                |
| 热读缓存         | 平台设置、币种/佣金、公开学习目录引入 Caffeine 缓存                                                                                                                                                                 |
| 可观测性         | 新增 Prometheus registry 与 AI provider 调用延迟指标；默认仍只暴露健康端点                                                                                                                                          |
| 部署             | 新增前后端 Dockerfile、Nginx SPA 配置、生产 Compose 与环境变量模板；生产禁用假 AI/无 SMTP 启动并拒绝 JWT 占位密钥；Compose 固定并信任唯一 Nginx 代理地址，且 Nginx 覆盖外部转发头以保留不可伪造的客户端 IP 限流语义 |
| 前端性能         | Vite 对框架、网络、图标依赖分 chunk                                                                                                                                                                                 |
| 文档治理         | 新增 README、CONTRIBUTING、SECURITY、CHANGELOG 与迁移政策                                                                                                                                                           |

## P0 与 P1 核验

| #   | 报告结论              | 核验与当前处理                                                                                                                                                                                                 |
| --- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | AI 调用嵌入数据库事务 | **部分准确，已修复关键路径。** `chat`、词汇、造句、测验、故事、推荐六个方法调用同步 provider，现均在事务外等待；发音和写作不调用 provider，其文件复制也已移到事务外，仅数据库元数据/日志使用短事务。           |
| 2   | Hikari 默认池过小     | **配置缺口，已改善。** 显式可调，不武断将默认提高至 30；先消除长事务才是根治。                                                                                                                                 |
| 3   | 无 Dockerfile         | **已确认并修复。** 已提供 backend/frontend 镜像和生产 Compose。                                                                                                                                                |
| 4   | 无 README/文档        | **已确认并修复基础交付。** 已提供项目、贡献、安全、变更及本核验文档。                                                                                                                                          |
| 5   | AI 响应不流式         | **成立但非即刻崩溃。** SSE/流式 provider 与前端增量呈现是独立 UX/API 项目，待推进。                                                                                                                            |
| 6   | 完全无异步处理        | **部分成立且已修复已证实部分。** 密码重置与教师审核的 SMTP 邮件已改为事务提交后异步投递，并在生产禁用 SMTP 时拒绝启动；当前异步队列仍是进程内 best-effort，进程崩溃可丢待投邮件，严格可靠性仍需持久化 outbox。 |
| 7   | JWT 无 refresh token  | **成立且值得做。** 涉及 token 旋转、HttpOnly cookie、数据库撤销与前端会话迁移，需独立安全变更。                                                                                                                |
| 8   | 完全无缓存层          | **原先成立于部分热读，已修复所列设置热读。** 平台/商务设置、公开目录与内容安全开关现使用短 TTL 缓存。                                                                                                          |
| 9   | i18n 覆盖极低         | **成立。** 是内容与产品交付工作，需按页面和翻译审校分批推进。                                                                                                                                                  |
| 10  | 无 CSP                | **已确认并修复。** API 安全配置及实际承载 SPA 的 Nginx 均设置 CSP。                                                                                                                                            |
| 11  | AI 端点无限流         | **已确认并修复单实例版本。** 多实例部署必须改为 Redis/网关共享计数。                                                                                                                                           |
| 12  | 全面 N+1 风险         | **不能按原说法确认。** 当前多个仓库已使用 `EntityGraph`；应以 SQL profiling 对具体列表接口继续核查。                                                                                                           |

## 后续优先级

1. 独立安全改造：refresh token 旋转、HttpOnly cookie 与访问 token 内存化。
2. 上线防护：邮件持久化 outbox、共享 AI/认证限流、对象存储、备份恢复演练、依赖/DAST 扫描与负载验证。
3. 用户体验：AI 流式输出、i18n 内容覆盖、前端测试与关键路径 E2E。
4. 持续治理：CSS/API/页面拆分、登录限流器优化、API 契约自动校验。
