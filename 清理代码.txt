请作为资深代码质量审计专家、重构专家和生产级维护性负责人，检查整个项目中是否存在无用的、累赘的、重复的、没有意义的、可以安全删除或简化的代码。

你的目标不是为了“少代码而少代码”，而是提升长期可维护性、清晰度、稳定性和生产质量。

请重点检查：

1. Dead code
- 未被调用的方法
- 未被使用的类
- 未被使用的 component
- 未被使用的 hook
- 未被使用的 util
- 未被使用的 DTO
- 未被使用的 repository 方法
- 未被使用的 service 方法
- 未被使用的 config
- 未被使用的 constants / enum
- 未被使用的 route
- 未被使用的 API client
- 未被使用的 test helper

2. 重复代码
- 重复的业务逻辑
- 重复的 API 调用封装
- 重复的 validation
- 重复的 mapping
- 重复的 error handling
- 重复的 UI component
- 重复的样式
- 重复的配置
- 重复的测试 setup

3. 过度设计
- 没有实际价值的 abstraction
- 没有必要的 wrapper
- 没有必要的 factory
- 没有必要的 interface
- 没有必要的 inheritance
- 没有必要的 generic
- 没有必要的 helper function
- 只被调用一次但增加理解成本的抽象

4. 无意义代码
- 空方法
- no-op 方法
- 永远不会执行的 branch
- 无意义 try/catch
- 无意义 null check
- 无意义 console.log
- 无意义 comment
- 注释掉的旧代码
- temporary code
- placeholder code
- fake / mock / dummy code 泄漏到真实代码里
- 只为了绕过 lint / test 的代码

5. 无用依赖和配置
- package / Maven 里未使用的依赖
- 重复依赖
- 过期但未使用的 dependency
- 无用 environment variable
- 无用 application config
- 无用 docker config
- 无用 script
- 无用 build plugin
- 无用 test config

6. 无用文件
- 已废弃页面
- 已废弃组件
- 已废弃 service
- 已废弃 DTO
- 已废弃 migration 草稿
- 已废弃 mock data
- 已废弃文档
- 已废弃脚本
- 未被引用的 asset / image / style file

============================================================
执行规则
============================================================

请严格遵守：

1. 先确认是否真的无用，再删除。
2. 不要因为暂时没看懂就删除。
3. 不要删除 public API、database migration、security config、critical test、文档契约或可能被外部使用的内容，除非有明确证据。
4. 不要做大范围无意义格式化。
5. 不要为了减少代码而破坏可读性。
6. 不要删除用于测试、fallback、安全、兼容性或 migration 的必要代码。
7. 每次删除都必须能解释为什么安全。
8. 删除后必须运行测试、build、lint 或 typecheck。
9. 如果不确定是否可删除，标记为 REVIEW，不要强删。

============================================================
检查方式
============================================================

必须执行：

1. 搜索未使用代码和重复代码。
2. 检查 import / export / route / API usage。
3. 检查前端页面和组件是否被真实引用。
4. 检查后端 controller / service / repository / DTO 是否被真实使用。
5. 检查测试是否仍然需要相关 helper。
6. 检查配置和依赖是否真的被使用。
7. 检查 mock / fake / dummy / placeholder 是否泄漏到生产代码。
8. 删除或简化可以安全处理的内容。
9. 删除后重新运行验证。
10. 如果删除会影响行为，必须停止并记录风险。

============================================================
输出格式
============================================================

最终输出必须包含：

1. Cleanup Scope
- 检查了哪些目录
- 检查了哪些前端区域
- 检查了哪些后端区域
- 检查了哪些配置、依赖、脚本和测试

2. Removable Code Findings
每一项必须包含：
- severity
- file path
- code/object name
- why it is unnecessary
- evidence that it is unused or redundant
- recommended action：delete / simplify / merge / keep / review
- status：deleted / simplified / kept / review

3. Implemented Cleanup
每一项必须包含：
- changed files
- removed or simplified code
- why safe
- behavior impact
- verification result

4. Not Removed Because Risky
每一项必须包含：
- file path
- why it looked unnecessary
- why it was kept
- what evidence is missing
- recommended next step

5. Verification
必须包含：
- commands run
- test result
- build result
- lint / typecheck result if available
- failures and reasons
- unverified items

6. Final Assessment
必须回答：
- 是否还有明显无用代码？
- 是否还有明显重复代码？
- 是否还有过度设计？
- 是否还有 mock / placeholder / no-op 泄漏？
- 是否还有需要人工确认才能删除的内容？
- 当前代码是否比清理前更清晰、更安全、更可维护？

============================================================
停止条件
============================================================

只有满足以下条件才可以说完成：

1. 已检查主要代码目录。
2. 已检查依赖和配置。
3. 已检查 mock / fake / dummy / placeholder。
4. 已删除或简化所有可以安全处理的无用代码。
5. 不确定的内容已明确标记 REVIEW，而不是乱删。
6. 删除后已运行可用验证命令。
7. 没有因清理导致测试、build 或核心功能失败。

如果没有满足这些条件，不允许说完成。
现在开始执行无用代码和累赘代码清理审计。
