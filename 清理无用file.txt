请作为资深代码库维护负责人和项目清理审计专家，检查整个项目中是否存在无用的、废弃的、未被引用的、重复的、临时的、可以安全删除的文件。

你的任务不是随便删除文件，而是：

先证明文件确实无用，再安全删除。
删除后必须验证项目仍然可以正常构建、测试和运行。

============================================================
必须重点检查的无用文件类型
============================================================

请检查是否存在：

1. 前端无用文件
- 未被引用的页面文件
- 未被引用的 component
- 未被引用的 hook
- 未被引用的 util
- 未被引用的 API client
- 未被引用的 route 文件
- 未被引用的 store / context
- 未被引用的 style / css / scss 文件
- 未被引用的 image / icon / asset
- 废弃 layout
- 废弃 mock data
- 废弃 story / demo / example 文件

2. 后端无用文件
- 未被使用的 controller
- 未被使用的 service
- 未被使用的 repository
- 未被使用的 DTO
- 未被使用的 mapper
- 未被使用的 util
- 未被使用的 config
- 未被使用的 provider
- 未被使用的 exception class
- 废弃 test helper
- 废弃 mock provider
- 废弃 sample data

3. 配置和脚本无用文件
- 未使用的 config 文件
- 废弃 environment 文件
- 重复 docker 文件
- 未使用 script
- 旧 build 文件
- 临时 migration 草稿
- 旧 OpenAPI / API spec 文件
- 旧文档或过期 README 草稿

4. 测试无用文件
- 已失效测试
- 跟真实代码无关的测试
- 已废弃 flow 的测试
- 未被使用的 fixture
- 未被使用的 test data
- 旧 snapshot
- 无意义 mock

5. 临时和垃圾文件
- backup 文件
- copy 文件
- old 文件
- temp 文件
- .bak
- .tmp
- .old
- unused
- deprecated
- legacy
- draft
- sample
- demo
- placeholder
- test-only leftover
- commented archive
- 生成物误提交
- build output 误提交
- log 文件误提交

============================================================
执行规则
============================================================

必须遵守：

1. 不要凭文件名直接删除，必须检查引用关系。
2. 不要删除数据库 migration 历史文件，除非明确是未使用草稿且未被应用。
3. 不要删除 public API contract、OpenAPI、README、env example、docker、CI 配置，除非确认已废弃且有替代。
4. 不要删除测试 fixture，除非确认没有测试引用。
5. 不要删除图片 / icon / asset，除非确认没有任何 import、CSS url、HTML reference 或 public path 使用。
6. 不要删除可能被动态 import、路由懒加载、反射、Spring 扫描、配置扫描使用的文件，除非有明确证据。
7. 不要删除安全、配置、provider、exception、migration、script 相关文件，除非确认无引用且无生产用途。
8. 不确定的文件必须标记 REVIEW，不要乱删。
9. 删除文件后必须重新运行验证。
10. 如果删除导致 build / test / lint 失败，必须恢复或修复。

============================================================
检查方式
============================================================

请按下面步骤执行：

1. 建立文件清单
- 列出项目所有主要目录和文件类型。
- 标记 frontend / backend / config / script / test / asset / doc。

2. 查找候选无用文件
搜索文件名和内容关键词：

- unused
- deprecated
- legacy
- old
- backup
- copy
- temp
- tmp
- draft
- sample
- demo
- mock
- fake
- dummy
- placeholder
- example
- test
- bak

3. 检查引用关系
对每个候选文件检查：

- import / export
- route reference
- API usage
- component usage
- CSS / asset reference
- test reference
- build config reference
- package / Maven reference
- Spring component scan / bean reference
- config reference
- script reference
- docker / CI reference
- README / docs reference
- dynamic usage risk

4. 分类处理
每个文件必须分类：

- DELETE：确认无用，可以安全删除
- KEEP：仍然使用或有生产价值
- REVIEW：可能无用，但证据不足，需要人工确认
- REPLACE：有替代文件，应迁移引用后删除旧文件
- ARCHIVE_RISK：看似废弃但可能有历史 / migration / 文档价值

5. 执行删除
只删除 DELETE 类文件。
REVIEW 不删除。
KEEP 不删除。
ARCHIVE_RISK 不删除。
REPLACE 必须先迁移引用，再删除。

6. 验证
删除后必须运行可用命令，例如：

- npm test / npm run test
- npm run build
- npm run lint
- npm run typecheck
- ./mvnw test
- ./mvnw -DskipTests package
- 其他项目实际可用命令

如果无法运行，必须说明原因。
不得伪造验证结果。

============================================================
特别注意
============================================================

以下文件默认高风险，不要轻易删除：

- database migrations
- security config
- auth config
- production config
- Docker / CI / deployment config
- environment example
- OpenAPI / API contract
- README / docs
- scripts
- test fixtures
- provider implementations
- exception handlers
- generated type files
- public assets
- route files
- Spring component scanned classes

只有在有明确证据表明它们无用，并且删除后验证通过时，才可以删除。

============================================================
输出格式
============================================================

最终输出必须包含：

1. File Cleanup Scope
- 检查了哪些目录
- 检查了哪些文件类型
- 哪些目录未检查以及原因

2. Candidate Unused Files
每个候选文件必须包含：
- file path
- reason flagged
- reference check result
- risk level
- decision：DELETE / KEEP / REVIEW / REPLACE / ARCHIVE_RISK
- evidence

3. Deleted Files
每个删除文件必须包含：
- file path
- why it was safe to delete
- references checked
- expected behavior impact
- verification result

4. Kept / Review Files
每个未删除但可疑文件必须包含：
- file path
- why it looked unused
- why it was kept
- what evidence is missing
- recommended next step

5. Verification
必须包含：
- exact commands run
- result
- failures if any
- build result
- test result
- lint / typecheck result if available
- unverified items and reasons

6. Final Assessment
必须回答：
- 是否删除了所有可安全删除的无用文件？
- 是否还有需要人工确认的疑似无用文件？
- 是否存在误删风险？
- 删除后项目是否仍可构建 / 测试 / 运行？
- 是否建议继续做下一轮深度清理？

============================================================
停止条件
============================================================

只有满足以下条件才可以说完成：

1. 已检查主要项目目录。
2. 已生成候选无用文件清单。
3. 每个候选文件已检查引用关系。
4. 只删除了有明确证据的无用文件。
5. 风险文件没有乱删，已标记 REVIEW。
6. 删除后已运行可用验证命令。
7. 没有因删除导致构建、测试或核心功能失败。
8. 最终报告清楚说明删除证据和剩余风险。

如果无法满足停止条件，不允许说完成。

现在开始执行无用文件清理审计。
