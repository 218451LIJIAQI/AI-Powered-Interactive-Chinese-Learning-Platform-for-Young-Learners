============================================================
必须全面提升的范围
============================================================

你必须主动检查并提升所有相关方面，包括但不限于：

1. Schema 设计

- 表结构是否还能更合理
- 字段类型是否还能更准确
- 字段长度是否还能更严谨
- decimal 精度是否还能更安全
- 时间字段是否还能更一致
- 表关系是否还能更清晰
- 业务边界是否还能更明确
- 数据模型是否还能更稳定、更可扩展、更适合长期演进

2. 数据完整性

- 主键设计是否还能更稳
- 外键是否完整
- unique constraint 是否足够
- nullability 是否严格
- check constraint 是否需要
- 默认值是否安全
- 是否还有业务不变量只靠应用代码保证
- 是否还有并发下可能产生脏数据、重复数据或非法状态的风险

3. Flyway Migration

- migration 顺序是否清晰
- migration 是否安全
- migration 是否可重复验证
- 是否存在 checksum/repair 风险
- 是否存在 schema drift 风险
- 是否存在破坏性迁移
- 是否存在环境依赖
- 是否还能提升 roll-forward 安全性
- 是否还能让未来维护者更容易理解和扩展

4. JPA / Hibernate 映射

- entity 是否与真实 schema 完全一致
- nullable、length、precision、scale 是否准确
- enum 映射是否安全
- relationship 是否正确
- fetch strategy 是否合理
- cascade 是否可能误删数据
- orphanRemoval 是否存在风险
- optional 是否与数据库约束一致
- 是否存在 N+1 查询
- 是否存在 join 膨胀
- 是否需要乐观锁
- 是否需要更严格的实体生命周期控制

5. Repository / Query / Index

- 每个查询是否都有合适索引
- 每个排序是否能命中索引
- 每个分页是否稳定
- composite index 顺序是否最优
- 是否存在重复索引
- 是否存在无效索引
- 是否存在缺失索引
- count / exists / lookup 是否高效
- hot path 查询是否能支撑数据增长
- repository 方法是否与数据库结构长期一致

6. Service / Transaction / Concurrency

- 事务边界是否足够安全
- 状态流转是否可靠
- 并发写入是否存在竞态
- 是否需要数据库级幂等约束
- 是否存在重复提交风险
- 是否存在只靠 Java 判断但数据库不兜底的问题
- 是否需要 optimistic locking
- 是否需要更明确的失败回滚策略
- 是否需要更强的业务不变量保护

7. 隐私与数据最小化

- 学生数据是否还能更少存储
- 学生数据是否还能更安全
- AI prompt/response 是否过度保留
- audit log 是否记录了不该记录的敏感内容
- token、password、secret、reset link 是否可能进入数据库或日志
- 上传文件元数据是否暴露过多
- 是否存在不必要的 PII 持久化
- 是否需要脱敏、摘要化、截断、最小化或保留期限控制

8. 审计与可追踪性

- teacher/admin 操作是否完整可追踪
- actor、target、action、timestamp、request id 是否完整
- 关键业务操作是否有审计路径
- 审计日志是否可用于问责
- 审计日志是否避免保存敏感正文
- 审计结构是否长期可查询、可分析、可扩展

9. 商务 / 支付 / 订单 / 退款 / 回调 / 分账

如果项目中存在相关模块，必须检查并提升：

- 金额字段精度是否正确
- currency 是否明确
- 第三方 transaction id 是否唯一
- payment callback 是否幂等
- order 状态是否可靠
- refund 是否可追踪
- payout 是否可审计
- 是否存在重复扣款风险
- 是否存在重复发货风险
- 是否存在重复退款风险
- 是否存在状态机错乱风险
- 是否存在金额计算精度风险

10. 测试与环境一致性

- 测试数据库是否足够接近 MySQL
- H2 与 MySQL 是否存在行为差异
- application-test.yml 是否可靠
- Docker Compose 是否稳定
- Flyway validation 是否真实有效
- Hibernate ddl-auto=validate 是否真正生效
- build/test/package 是否能验证数据库契约
- 是否需要增加更可信的数据库集成验证

11. 配置与部署安全

- datasource 是否清晰
- host/port 是否一致
- charset 是否统一
- collation 是否统一
- timezone 是否明确
- SQL mode 是否安全
- Flyway clean 是否禁用
- validate-on-migrate 是否启用
- ddl-auto 是否为 validate
- example 配置是否安全
- .env.example 是否不会误导部署
- 脚本是否不会掩盖真实问题

12. 长期可维护性

- 命名是否统一
- migration 是否易读
- entity 是否表达准确
- repository 是否清晰
- service 边界是否明确
- dto 是否避免泄露内部字段
- 目录结构是否容易维护
- 是否存在未来开发者容易误用、踩坑或破坏数据一致性的地方
- 是否需要补充注释、约定或验证脚本
