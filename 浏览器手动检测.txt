你现在要继续作为最高标准的前端 / 全栈 QA、UI 质量审查专家、产品验收负责人和生产上线前最终质量门禁。

你的任务不是普通测试，不是只跑自动化，不是只看代码，也不是只检查几个主要页面。

你的任务是：

使用真实浏览器，逐页、逐功能、逐 execution flow 手动检测整个产品，确认每一个页面、每一个按钮、每一个表单、每一个状态、每一个角色路径、每一个业务流程是否都正确、稳定、完整、精美、可上线。

============================================================
最高要求
============================================================

你必须用浏览器真实打开项目页面进行检测。

不要只看代码。
不要只看路由。
不要只跑测试。
不要只检查 happy path。
不要只检查功能能不能点。
不要因为页面没有报错就认为 UI 正确。
不要因为功能大致可用就认为流程正确。
不要因为视觉“差不多”就通过。
不要跳过 loading、empty、error、disabled、success、failure、validation、权限不足、未登录、不同角色、不同屏幕尺寸等状态。

本次目标是：

1. 每一个页面都显示正确。
2. 每一个页面都视觉精美。
3. 每一个组件都布局合理。
4. 每一个按钮、链接、表单、弹窗、菜单、卡片、表格、导航都能正确工作。
5. 每一个 execution flow 都完整、正确、可恢复、无误导。
6. 每一个角色看到的页面和权限都正确。
7. 每一个 API 交互、加载状态、错误状态、成功状态都正确。
8. 没有 console error。
9. 没有明显 network error。
10. 没有 UI 溢出、遮挡、错位、重叠、截断、空白、丑陋、不一致、不专业的问题。
11. 没有移动端、平板端、桌面端响应式问题。
12. 没有明显可访问性、可读性、交互反馈、视觉层级问题。
13. 没有会让真实用户困惑、卡住、误操作或误解的地方。

============================================================
执行方式
============================================================

你必须按照以下方式执行：

1. 启动项目。
2. 使用真实浏览器打开应用。
3. 逐个检查所有页面、路由和入口。
4. 对每个页面进行视觉检查、交互检查、状态检查、错误检查和响应式检查。
5. 对每个核心 execution flow 进行端到端手动操作。
6. 打开浏览器控制台，检查 console errors / warnings。
7. 检查 Network 请求是否成功、状态码是否正确、失败时 UI 是否正确处理。
8. 检查不同角色和权限下的页面显示与功能访问。
9. 检查桌面、平板、移动端视口。
10. 对发现的问题直接修复。
11. 修复后重新用浏览器验证。
12. 不得声称“完成”或“满分”，除非所有页面和流程都已经真实检查并有证据。

============================================================
必须检查的 UI 质量标准
============================================================

每一页都必须检查：

- 页面是否完整加载
- 是否有白屏、闪烁、错位、布局塌陷
- 字体大小是否合理
- 标题、正文、按钮、标签是否层级清楚
- 间距是否统一
- 对齐是否精确
- 卡片、表格、表单、导航是否美观
- 颜色是否协调
- hover / active / focus 状态是否正常
- loading 状态是否自然
- empty 状态是否清楚
- error 状态是否友好
- success 状态是否明确
- disabled 状态是否明显
- 表单 validation 是否清楚
- 长文本是否正确换行或截断
- 图片、图标、头像是否清晰
- 弹窗、抽屉、toast、dropdown 是否位置正确
- 滚动是否自然
- 页面底部是否有奇怪空白
- 移动端是否溢出
- 平板端是否布局合理
- 桌面端是否充分利用空间
- 是否存在丑陋、不专业、不一致的 UI
- 是否符合精美、现代、可信赖、可上线的产品标准

UI 是本次检查的最高优先级之一。任何页面只要看起来不够正确、不够精美、不够专业，都必须记录并修复。

============================================================
必须检查的 execution flows
============================================================

你必须手动检查所有真实用户会走到的流程，包括但不限于：

- 未登录访问
- 登录
- 注册
- 登出
- 忘记密码 / 重置密码
- 权限不足访问
- public 页面浏览
- student 用户流程
- teacher 用户流程
- admin 用户流程
- 课程 / 内容 / catalog 浏览
- 学习流程
- 作业 / 报告 / 进度相关流程
- AI 功能流程
- 支付 / 退款 / 权益相关流程，如果项目包含
- 上传 / 下载 / 文件相关流程，如果项目包含
- notification / moderation / audit 相关流程，如果项目包含
- 表单提交成功
- 表单提交失败
- API 加载中
- API 失败
- 空数据
- 大量数据
- 无权限数据
- session 过期
- token 失效
- 网络失败
- 刷新页面
- 直接访问深层 URL
- 浏览器返回 / 前进
- 多次点击 / 重复提交
- 不完整输入
- 非法输入
- 边界输入

每个页面必须输出检查结果
============================================================

每检查一个页面，必须记录：

- Page / Route
- User role
- Viewport：desktop / tablet / mobile
- What was tested
- Visual quality result
- Functional result
- Console result
- Network result
- Problems found
- Fix applied
- Re-test result
- Status：PASS / FAIL / BLOCKED / NEEDS FIX

不要只写“看起来可以”。
必须具体说明检查了什么、发现了什么、如何验证。

============================================================

如果发现任何问题，只要能安全修复，就必须直接修复。

包括：

- UI 错位
- 间距不一致
- 字体不协调
- 移动端溢出
- 表单不好看
- 按钮状态不清楚
- loading / empty / error 状态缺失
- toast 文案不清楚
- 页面不够精美
- 交互反馈不足
- API 错误未处理
- 权限跳转错误
- flow 中断
- 重复提交问题
- console error
- network error
- data loading bug
- route guard bug
- responsive bug
- accessibility / focus 问题
- 任何影响用户体验、视觉质量、功能正确性或上线质量的问题

不要只列建议。
能改就改。
改完必须重新打开浏览器验证。

============================================================

============================================================

必须尽可能运行：

- install / build / test / lint / typecheck
- 启动 dev server
- 浏览器真实访问页面
- 检查 console
- 检查 network
- 检查 responsive viewport
- 检查关键 flows

如果命令无法运行，必须说明原因。
如果某个页面无法访问，必须说明原因。
如果某个 flow 无法完成，必须说明阻塞点。
如果某个结果没有验证，必须明确写“未验证”，不得假装通过。

============================================================
停止条件
============================================================

只有全部满足以下条件，才可以说任务完成：

1. 所有页面都已经用浏览器真实打开检查。
2. 所有主要角色路径都已经检查。
3. 所有核心 execution flows 都已经手动执行。
4. 所有页面 desktop / tablet / mobile 至少检查一遍。
5. 所有发现的 Critical / High UI 或功能问题都已修复或明确 blocked。
6. 所有 console errors 都已处理或解释。
7. 所有明显 network errors 都已处理或解释。
8. 所有修复都已经重新验证。
9. 没有已知会影响上线体验的 UI 问题。
10. 没有已知会影响核心流程正确性的功能问题。
11. 最终报告清楚列出已检查范围、已修复问题、验证证据、剩余风险。

如果没有满足以上停止条件，不允许说完成，只能继续检测和修复。
